# Phase 1H-H — Client-Centric Mobile Redesign

## Approved information architecture

Phase 1H-H changes the mobile app from a dashboard-first layout to a client-centric workflow:

- Clients
- Reminders
- Outstanding
- Turnover
- Settings

The previous Dashboard, Work, Finance, Files and More foundations remain reusable screens/components, but they are no longer root navigation destinations.

## Client workspace

Each client profile now acts as the operational workspace and exposes:

- Overview
- Projects / Jobs
- Tasks
- Reminders
- Invoices
- Project Expenses
- Quotes
- Documents

Client-scoped screens preselect the selected client and request server-side client-scoped collections where the mobile API supports filtering. Server-side tenant authorization remains authoritative.

Clients sort alphabetically and support multi-field search. First Name and Last Name are the only required Client fields; address remains optional. Premium banners remain part of the accepted presentation.

## Form parity contract

The audited pilot web CRM forms are the source of truth for business meaning, required fields, select options and validation semantics.

### Add Client

Mobile includes the audited name, contact, status, address and notes fields:

- First Name
- Last Name
- Company Name
- Email Address
- Phone Number
- Website
- Status
- Address Line 1
- Address Line 2
- City
- County/State
- Postcode
- Country
- Notes

### Projects / Jobs

The approved simplified mobile Project form excludes Project Type. Date/time fields use the approved picker controls where applicable.

Project Expenses use ONE authoritative Expense record. The standalone Client-level view aggregates expenses across only that Client's Projects, with related Project labels. The Project-level view filters the same records. Client-level Add Expense selects one of that Client's Projects, then reuses Date / Description / Amount. Save, Edit and Delete remain consistent across both views without duplicates. Empty Expense and no-Project states are distinct. Owner Samsung UAT: PASS; functionality frozen.

### Tasks

Tasks are distinct from Reminders. The permanent contract includes `GET /tasks`, `POST /tasks`, `GET /tasks/{id}`, `POST /tasks/{id}` and `DELETE /tasks/{id}`. Update reuses the normal permission callback, server-derived tenant context, Task repository and existing validation. Client/Project relationships remain tenant-validated.

### Reminders

Mobile reminders preserve their own workflow with client, optional project, reminder title, date, time, priority, status and description. Reminders are available both as a standalone root tab and inside each client workspace; both views use the same underlying reminder records.

### Invoices

Invoice creation now preserves invoice line items:

- Description
- Quantity
- Unit Amount
- Line Total calculated by Daphnex CRM after save

The form also includes client, optional project, status, invoice date, due date and notes. Invoice numbers remain generated by Daphnex CRM.

### Documents

Documents remain in the client workspace and continue to use Android `ACTION_OPEN_DOCUMENT` through the existing safe document picker service. Supported mobile upload types remain PDF, DOC, DOCX, JPG/JPEG and PNG. The web audit’s WEBP parity is deferred until backend/mobile validation is expanded safely.

## Outstanding and Turnover

Outstanding uses authoritative invoice balances/statuses, supports partial payments and preserves separate payment history entries. Payment History displays the business Payment Date only, alongside amount, method and reference. Recording time is omitted for this release; backend timestamps and payment calculations are preserved. P1 Recorded Time is deferred in `payment-recorded-time-deferred.md`.

Turnover is monthly and shows No., Month, Total Invoices and Total Invoiced. Invoice creation/deletion adjusts the relevant month's count and total. Payment status does not change Turnover. Expenses and Profit/Loss are absent. Owner Samsung UAT: PASS; functionality frozen.

## Quotes and PDF workflows

Quotes are client-scoped and support CRUD, Quotation PDF viewing/download and actual PDF attachment sharing through WhatsApp. Quotes contribute nothing to Turnover or Outstanding. Invoice PDF/WhatsApp workflows are preserved.

## Permanent backend deployment boundary

Permanent backend contracts provide tenant-scoped business workflows and client filtering. Temporary Task/Quote helpers remain installed on pilot until separately approved permanent deployment and validation. They are not the permanent architecture. No deployment or helper removal is authorized by this document.

## Security notes

The redesign preserves:

- bearer-token authentication
- commercial session bootstrap
- role-aware visibility
- entitlement checks
- access-removal session clearing
- document URL resolving protections
- Android storage/media permission compliance
- tenant-scoped API expectations

No credentials, Stripe keys, Cloudflare URLs, localhost/tunnel runtime API authority, APK/AAB artifacts or signing changes are introduced by this phase.
